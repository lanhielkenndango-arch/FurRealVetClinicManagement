# Data Dictionary

## Database Name

`furrealvetclinicmanagement`

## Database Description

The database stores the main records used by FurReal Vet Clinic Management. It contains client accounts, pet profiles, clinic services, visit records, and visit service details. The structure follows a transaction header and transaction detail pattern through the `visits` and `visit_services` tables.

## Relationship Summary

- One client can own many pets.
- One client can have many visit records.
- One pet can appear in many visit records.
- One visit can contain many selected services.
- One clinic service can appear in many visit service detail records.

## Table: clients

Stores client account and contact information.

| Field Name | Data Type | Key / Constraint | Description |
| --- | --- | --- | --- |
| `client_id` | `INT` | Primary Key | Unique client identifier generated by the system. |
| `first_name` | `VARCHAR(80)` | Not Null | Client first name. |
| `last_name` | `VARCHAR(80)` | Not Null | Client last name. |
| `phone` | `VARCHAR(30)` | Not Null, Unique | Client phone number used for contact and login. |
| `email` | `VARCHAR(120)` | Not Null, Unique | Client email address used for login. |
| `password_text` | `VARCHAR(120)` | Not Null | Client password value for project login demonstration. |

## Table: pets

Stores pet records linked to registered clients.

| Field Name | Data Type | Key / Constraint | Description |
| --- | --- | --- | --- |
| `pet_id` | `INT` | Primary Key, Auto Increment | Unique pet identifier. |
| `client_id` | `INT` | Foreign Key, Not Null | References `clients.client_id`; identifies the owner of the pet. |
| `pet_name` | `VARCHAR(80)` | Not Null | Name of the pet. |
| `pet_type` | `VARCHAR(40)` | Not Null | Type of animal, such as dog or cat. |
| `breed` | `VARCHAR(80)` | Not Null | Pet breed. |
| `age` | `INT` | Not Null | Pet age. |

Relationship:

`clients.client_id` 1 to many `pets.client_id`

## Table: clinic_services

Stores the service catalog offered by the clinic.

| Field Name | Data Type | Key / Constraint | Description |
| --- | --- | --- | --- |
| `service_id` | `INT` | Primary Key, Auto Increment | Unique service identifier. |
| `service_name` | `VARCHAR(100)` | Not Null | Name of the clinic service. |
| `category` | `VARCHAR(60)` | Not Null | Service category, such as General, Vaccines, Dental, or Grooming. |
| `price` | `DECIMAL(10,2)` | Not Null, Default `0.00` | Base price of the service. |
| `service_date` | `VARCHAR(40)` | Not Null, Default empty string | Date value used by the service management module. |

## Table: visits

Stores visit or appointment records. This acts as the transaction header table.

| Field Name | Data Type | Key / Constraint | Description |
| --- | --- | --- | --- |
| `visit_id` | `INT` | Primary Key, Auto Increment | Unique visit identifier. |
| `client_id` | `INT` | Foreign Key, Not Null | References `clients.client_id`; identifies the client for the visit. |
| `pet_id` | `INT` | Foreign Key, Not Null | References `pets.pet_id`; identifies the pet for the visit. |
| `visit_date` | `VARCHAR(40)` | Not Null | Scheduled date of the visit. |
| `status` | `VARCHAR(30)` | Not Null, Default `Scheduled` | Visit status, such as Scheduled, Completed, or Cancelled. |
| `total` | `DECIMAL(10,2)` | Not Null, Default `0.00` | Total amount of selected services for the visit. |

Relationships:

`clients.client_id` 1 to many `visits.client_id`

`pets.pet_id` 1 to many `visits.pet_id`

## Table: visit_services

Stores selected services for each visit. This acts as the transaction detail or junction table between visits and clinic services.

| Field Name | Data Type | Key / Constraint | Description |
| --- | --- | --- | --- |
| `visit_service_id` | `INT` | Primary Key, Auto Increment | Unique visit service detail identifier. |
| `visit_id` | `INT` | Foreign Key, Not Null | References `visits.visit_id`; identifies the parent visit record. |
| `service_id` | `INT` | Foreign Key, Not Null | References `clinic_services.service_id`; identifies the selected service. |
| `quantity` | `INT` | Not Null, Default `1` | Number of times the service is applied in the visit. |
| `line_total` | `DECIMAL(10,2)` | Not Null, Default `0.00` | Amount for the selected service line. |

Relationships:

`visits.visit_id` 1 to many `visit_services.visit_id`

`clinic_services.service_id` 1 to many `visit_services.service_id`

## Foreign Key Summary

| Foreign Key Field | References | Relationship Purpose |
| --- | --- | --- |
| `pets.client_id` | `clients.client_id` | Connects each pet to its owner. |
| `visits.client_id` | `clients.client_id` | Connects each visit to a client. |
| `visits.pet_id` | `pets.pet_id` | Connects each visit to a pet. |
| `visit_services.visit_id` | `visits.visit_id` | Connects transaction details to the visit header. |
| `visit_services.service_id` | `clinic_services.service_id` | Connects selected services to the service catalog. |

## Data Integrity Rules

- Every table has a primary key.
- Pet records require an existing client.
- Visit records require an existing client and pet.
- Visit service records require an existing visit and clinic service.
- Deleting a client cascades to related pet records.
- Deleting a visit cascades to its visit service detail records.
- Visit and service relationships prevent orphan transaction records.
